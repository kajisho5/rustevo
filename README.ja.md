# rustevo

**エージェントが進化させるアプリのための Rust フレームワーク。すべての変更が、再演できる記録として残る。**

English: [README.md](README.md)

エージェントがアプリを 50 回書き換えたあと、実際に何が変わったのかをどうやって確かめるか。
rustevo は、信用ではなく証跡で答えます。

1. **すべての実行が記録になる。** 操作、時刻、外から返ってきた結果は、すべて 1 本の記録を通ります。同じ記録を同じビルドに流すと、同じ状態と同じ画面の木が 1 バイトも違わず再現されます。
2. **変更は先に宣言し、あとで実測する。** 変更の前に、何が変わるかをエージェントが書きます。前の世代の記録を新しいビルドで再演し、宣言の外で違いが出たら、その世代は不合格です。
3. **すべての変更が世代になる。** ソース・plan・ロジック・証跡の組で、親の世代とハッシュでつながります。不合格になった試みも台帳に残ります。

状態: v0.1、画面なし（ヘッドレス）。描画はまだありません。仕様はまだ固まっていません。

## 動いているもの

デモはポモドーロタイマーです。12 回の変更を試み、10 回が合格、2 回が不合格でした。

```
$ evo ledger apps/pomodoro
0001 sealed   最初の版。25分の集中タイマー
0002 sealed   ロジックの整理。動きは変えない             ← 全記録が一致
0003 sealed   残り時間の表示に「残り」をつける           ← 宣言した所だけ相違
0004 rejected 開始ボタンの文言を日本語にする             ← 集中時間まで変えていた
0005 sealed   開始ボタンの文言を日本語にする（4のやり直し）
0006 sealed   集中が終わったら5分の休憩に入る
0007 sealed   完了回数を保存する
0008 sealed   完了回数を0に戻すボタンを足す
0009 rejected 残り時間を5分とばすボタンを足す            ← 残り時間が負になった
0010 sealed   休憩の間だけとばせるようにする（9のやり直し）
0011 sealed   取り組むことの名前を入力できるようにする
0012 sealed   終わった集中を一覧に残す
```

世代 4 がこの仕組みの要です。エージェントの宣言は「ボタンの文言を変える」だけでした。
plan の差分も「`#start` だけが違う」と言っていました。しかしロジックの中で、集中時間が 25 分から 20 分に変わっていました。
親の世代の記録を流し直すと、宣言にない `remaining` が 1 ステップ目から違っていたため、不合格になりました。

```json
"undeclared": { "fields": ["remaining"], "derives": ["label"], "nodes": ["timer"] }
```

全部、自分で確かめられます。

```
./scripts/check.sh
```

保存されたファイルだけから全世代を検証し直します。続けて、記録の書き換え・判定の書き換え・台帳の行の削除・ロジックの差し替えが、それぞれ検出されることを確かめます。

## アプリの書き方

画面と状態の形は `.evo` に宣言し、ロジックは Rust で書きます（例は [README.md](README.md) と `apps/pomodoro/`）。

言語は 14 構文で閉じています: `app` `use` `state` `derive` `invariant` `every` `view` `style`、要素、`if` `for` `on` `set` `do`。

ロジックの関数は、状態を読んで「変更」と「外への依頼」をデータとして返すだけです。WebAssembly（どこでも同じに動く中間形式）にして、外の機能を一切渡さずに動かすので、時計も通信もファイルも直接は読めません。依頼はランタイムが実行して結果を記録し、再演のときは記録された結果をそのまま返します。

## 使い方の流れ

```
evo build apps/pomodoro                 # .evo → plan、ロジック → wasm
evo run   apps/pomodoro s1              # 記録つきで始める
evo tap   apps/pomodoro s1 start        # 入力はすべて記録の 1 行になる
evo clock apps/pomodoro s1 +60000       # 時計はドライバが進める
evo state apps/pomodoro s1
# アプリを直し、change.json に宣言を書く:
#   { "intent": "...", "fields": [], "derives": [], "nodes": ["start"], "effects": [] }
evo carry  apps/pomodoro                # 判定の下見
evo seal   apps/pomodoro --by "agent"   # 判定して世代を書く
evo verify apps/pomodoro                # 台帳を最初から検証
evo verify apps/pomodoro --rebuild      # 各世代のソースからロジックを作り直し、保存分と比べる
evo site   apps/pomodoro --out _site    # 公開台帳のページを書き出す（先に検証する）
```

ドライバの操作: 見る `tree` `state` `journal`、入れる `tap` `type` `clock` `respond`（入れる操作は必ず記録に残る）。

## Exact との関係

[Exact](https://github.com/expo/exact) のほうが速く、複数の環境で本物の画面を描き、TypeScript でもロジックを書けます。それが必要なら Exact を使ってください。rustevo は速さや対応環境の数では競いません。

rustevo が扱うのは、エージェントによる変更が積み重なったときに「どの動きが変わり、どの動きが変わっていないか」を示し、その証拠を誰でも確かめ直せる形で残すことです。

## まだできないこと

- 描画とスクリーンショットはありません。画面は論理的な木です。
- `evo verify --rebuild` は、各世代に保存されたソースからロジックを作り直し、保存された `.wasm` と 1 バイトも違わないことを確かめます。ただし作り直しに使う Rust のバージョン・依存の固定ファイル・共有の部品・`logic/Cargo.toml` は、リポジトリの**今の**ものです。これらを変えると、古い世代は一致しなくなります（その場合は不一致として報告されます）。
- 台帳はハッシュの連鎖で、署名はありません。途中の書き換えは検出できますが、それ以降の全世代を矛盾なく作り直された場合は、以前のハッシュが別の場所（git の履歴など）に残っていないと検出できません。
- 持ち越し再演は要素を id で比べます。兄弟の並び替えは報告されません。
- 式の型は実行時に検査します（コンパイル時の検査は未実装）。
- 1.0 前はやらないこと: Android、Windows、デバイス機能、ビジュアルエディタ、JavaScript のロジック層、互換性の約束。
